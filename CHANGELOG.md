# Belyaev DNT — журнал изменений релиза

Короткая версия для этого конкретного релиза. Полная история версий —
в [DEVELOPMENT.md](DEVELOPMENT.md#история-версий).

## 5.9.2 (2026-08-18) — сборка «chrome-yandex-opera», проверена и упакована

Эта версия впервые собрана как готовый к установке пакет. Ветка
исходников `5.9.2` уже содержала часть багфиксов (см. ниже), но
распространявшийся ZIP (`belyaev-dnt-v5.9.1 (chrome-yandex-opera).zip`)
всё ещё был собран из **старой, не исправленной** копии кода — именно
её пользователь ставил в браузер, и именно там наблюдались ошибки в
консоли `chrome://extensions` → «Ошибки»:

```
Executing inline script violates the following Content Security Policy
directive 'script-src 'self''... The action has been blocked.
Uncaught ReferenceError: seed is not defined   (×5)
```

### Исправлено в этом релизе

1. **`seed is not defined` — движок подмены отпечатка не работал на
   уровнях 2–5** (т.е. везде, кроме минимального уровня 1). Функции
   `applyBehaviorNoise()`/`applyTrackerPoisoning()` были объявлены и
   вызывались снаружи `apply()`, но использовали переменные (`seed`,
   `nextNoise`, `wrap`, `randId`), существующие только внутри неё.
   Первая же обращение к `seed` кидало `ReferenceError`, что обрывало
   выполнение всего скрипта ДО вызова `apply()` — ни User-Agent, ни
   экран, ни часовой пояс, ни canvas/WebGL не подменялись, хотя
   HTTP-заголовки (отдельный механизм) продолжали меняться. Это делало
   пользователя **более узнаваемым**, чем без расширения вовсе
   (JS-отпечаток и заголовки расходились). Самый серьёзный дефект в
   этом релизе. → `engine.js`
2. **CSP блокировала страницу самопроверки `test.html` целиком.**
   Инлайновый `<script>` запрещён политикой `script-src 'self'`,
   которую Chromium выставляет всем страницам расширений в
   Manifest V3, — таблица результатов оставалась пустой. Код вынесен
   во внешний `test.js`. → `test.html`, новый файл `test.js`
3. **`cookieconsent.js` кликал по кнопкам вне cookie-баннеров** —
   селектор `button[class*="reject"]` и поиск по тексту («отклонить»,
   «reject» и т.п.) не были ограничены баннером и могли нажать,
   например, «Отклонить платёж» или «Отклонить» в приглашении
   календаря. Теперь поиск по тексту ограничен контейнерами с
   `cookie`/`consent`/`gdpr` в id/class/aria-label.
4. **Обнаружение кражи данных из полей форм не работало.** Перехват
   `.value` жил в ISOLATED-мире и не видел чтения из скриптов страницы
   (MAIN-мир). Разделено на `formguard-main.js` (MAIN, перехват) и
   `formguard.js` (ISOLATED, проверка состояния + UI), связь — через
   `CustomEvent`.
5. **Переключатель «Динамическая защита» в попапе ничего не делал.**
   Режим читался асинхронно после того, как движок уже отработал
   синхронно на `document_start`, и смена режима не перерегистрировала
   скрипты. Добавлены `world/mode-static.js` / `world/mode-dynamic.js`
   по аналогии с уровнями защиты; `protectionMode` добавлен в список
   изменений storage, вызывающих перерегистрацию.
6. Удалён неиспользуемый файл `mode.js` — не был указан ни в одной
   секции `content_scripts` манифеста, мёртвый код.

### Не изменялось

- Логика уровней защиты 1–5, блокировка рекламы/трекеров (DNR-правила),
  формат и проверка лицензионных кодов, локализация — без изменений
  по содержанию, только перепакованы вместе с багфиксами выше.
- `firefox/` и `server/` из родительского пакета `v5.9.1-full` в этот
  релиз не входят — задание охватывало сборку `chrome-yandex-opera`
  (Chrome, Яндекс Браузер, Opera — все на движке Chromium, отдельной
  сборки под Yandex/Opera не требуется, один и тот же пакет Manifest V3
  подходит всем трём).

### Файлы релиза

- `belyaev-dnt-v5.9.2 (chrome-yandex-opera)/` — исходники расширения,
  готовые к загрузке через «Загрузить распакованное расширение»
  (chrome://extensions, browser://extensions, opera://extensions —
  во всех трёх режим разработчика включается одинаково).
- `belyaev-dnt-v5.9.2 (chrome-yandex-opera).zip` — тот же пакет в архиве.
- `CHECKSUMS_SHA256.txt` — контрольные суммы для проверки целостности.
- `SECURITY-AUDIT-TOOLS.md` — методология и перечень инструментов,
  которыми проверялась безопасность (≥ 10).
- `DEVELOPMENT.md` — полная техническая документация и история версий.

### Как проверить, что баг действительно устранён

1. Установите пакет, включите защиту (любой уровень 2–5).
2. Откройте `chrome://extensions` → карточка расширения → «Ошибки» —
   список должен быть пуст (кнопка «Ошибки» не будет отображаться,
   если ошибок ноль).
3. В попапе расширения откройте «О расширении» → тестовые сайты →
   встроенная страница самопроверки: вверху появится зелёный баннер
   «✓ engine.js применился…», таблица ниже заполнится значениями,
   отличными от реальных при включённой защите.
