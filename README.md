# Belyaev DNT — браузерное расширение для Google Chrome и Яндекс Браузера, которое закрывает цифровой отпечаток пользователя и корпоративных рабочих мест. Оно перехватывает попытки трекинга в браузере и синхронно подменяет данные согласованным профилем до того, как их прочитает скрипт сайта.

# Цель проекта — сократить объём данных, которые обычные пользователи и сотрудники отдают наружу, не меняя привычный браузер и рабочие процессы.

# Зачем это нужно
Цифровой отпечаток как риск. 99.9% браузеров и людей уникально идентифицируются по совокупности параметров: экран, шрифты, GPU, аудио, WebRTC, Client Hints, часовой пояс и десятки других характеристик. На основе этих отпечатков строятся профили активности, конкурентная разведка и таргетированный фишинг.

Корпоративные устройства «светятся» в любом месте. Даже за VPN и без явной авторизации корпоративный браузер можно различить на сторонних ресурсах и платформенных трекерах.
Типичный трекер считывает ~76 параметров устройства, связывает действия в единый профиль и отдаёт их третьим сторонам без явного контроля со стороны компании.
Belyaev DNT делает «меньше данных наружу — меньше поверхность атаки» практической реальностью для рабочих мест, отделов под риском и B2B/B2C‑сценариев.




 5.4.0 — аудит кода и переработка проверки адресов

**Исправлены дефекты:**

- **Правила для сайтов игнорировались content-скриптами.** `getNoticeState`
  возвращал глобальный уровень защиты без учёта персонального правила
  домена. Из-за этого на сайте-исключении всё равно скрывалась реклама, а
  карточка уведомления показывала неверный уровень. Теперь обработчик
  определяет домен отправителя и применяет его правило.
- **Подстановка имени домена в HTML.** Имя хоста вставлялось в разметку
  баннера и блокирующего экрана через шаблонную строку. Заменено на
  `textContent` — теперь содержимое домена не может повлиять на разметку.
- **Неограниченный рост журнала блокировок.** `blockedLog` пополнялся без
  лимита и со временем упёрся бы в квоту `chrome.storage.local`. Добавлена
  обрезка до 200 самых частых записей.
- **Паттерн исполняемых файлов проверялся по имени домена**, хотя
  предназначен для пути URL, и потому практически никогда не срабатывал.

**Переработан модуль проверки адресов:**

- Разделены паттерны для имени домена и для пути с параметрами.
- Добавлены три уровня вердикта: `safe`, `suspicious`, `dangerous`.
  Косвенные признаки риска больше не блокируют сайт, а показывают
  предупреждение с перечнем причин.
- Каждое правило содержит понятное текстовое объяснение, которое видит
  пользователь, — вместо общей фразы про фишинг.
- Добавлены эвристики: бесплатные доменные зоны, избыточная вложенность
  поддоменов, IP вместо домена, punycode.
