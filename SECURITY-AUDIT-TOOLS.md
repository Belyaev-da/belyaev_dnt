# Belyaev DNT v5.9.2 - методология и инструменты проверки безопасности

Этот файл честно описывает, **чем именно** проверялся код перед релизом:
что было реально выполнено в рамках этого аудита, и что дополнительно
рекомендуется прогнать перед публикацией в Chrome Web Store / Opera
Add-ons / Yandex Store. Раздутого списка «для галочки» здесь нет -
каждый пункт ниже либо применялся, либо явно помечен как рекомендация.

## Часть 1. Инструменты и методы, применённые в этом аудите

1. **Ripgrep (`rg`) - полнотекстовый поиск по кодовой базе.**
 Регулярными выражениями искали опасные конструкции: `eval(`,
 `new Function`, `document.write`, `innerHTML`/`outerHTML`,
 `postMessage`, `Math.random` в местах, где важна криптостойкая
 случайность, и т.п. - по всем `.js`/`.json`/`.html` файлам сборки.
2. **Ручной построчный код-ревью (line-by-line reading).** Каждый файл
 расширения - `manifest.json`, `background.js`, `engine.js` и все
 content scripts, `lib/*.js`, `popup/*` - прочитан целиком, а не по
 диагонали; логика проверена вручную, а не только по грепу.
3. **Трассировка области видимости переменных (scope/closure audit).**
 Именно этим способом обнаружен и подтверждён главный баг релиза -
 `ReferenceError: seed is not defined`: прослежено, в каком замыкании
 объявлена каждая переменная (`seed`, `nextNoise`, `wrap`, `randId`)
 и откуда именно она вызывается.
4. **Аудит потоков вывода в DOM (innerHTML vs textContent).** Каждое
 использование `innerHTML` в проекте проверено на источник данных:
 статическая разметка/захардкоженные строки - допустимо;
 данные, зависящие от страницы/URL/пользовательского ввода -
 обязаны идти через `textContent` или `createElement`+`textContent`.
5. **Аудит Content-Security-Policy для страниц расширения.**
 Проверено соответствие `manifest.json` политике Manifest V3
 (`script-src 'self'` по умолчанию для `chrome-extension://` страниц,
 без права на `'unsafe-inline'`) - этим найден баг с инлайн-скриптом
 в `test.html`.
6. **Аудит `manifest.json` / permissions.** Проверены `permissions`,
 `host_permissions`, `web_accessible_resources`,
 `content_scripts` (`matches`, `all_frames`, `world`, `run_at`) на
 избыточность и соответствие принципу минимальных привилегий.
7. **PowerShell (`Get-FileHash`, `Compare-Object`, `Select-String`,
 `Get-ChildItem`) - целостность и сравнение сборок.** Использован для
 сравнения нескольких копий кода в поставке (обнаружено, что
 распространявшийся ZIP собран из **устаревшей** копии `engine.js`,
 тогда как рядом лежала уже исправленная), и для расчёта контрольных
 сумм SHA-256 (см. `CHECKSUMS_SHA256.txt`).
8. **Сравнительный diff-анализ версий (regression check).** Построчное
 сравнение нескольких копий одного и того же файла внутри поставки
 (`chrome-yandex-opera/engine.js` vs
 `belyaev-dnt-v5.9.1 (chrome-yandex-opera)/chrome-yandex-opera/engine.js`)
 - так подтверждено, какая копия содержит фикс, а какая нет.
9. **Проверка криптографических примитивов.** `lib/license.js`
 проверен на источник случайности (`crypto.getRandomValues` с
 фолбэком на `Math.random()` только для не security-critical путей),
 алгоритм и режим (AES-GCM через Web Crypto API), формирование IV,
 константность сравнений - используется ли где-либо небезопасное
 сравнение секретов через `==`/`!=` вместо constant-time.
10. **Проверка сетевых точек выхода (egress audit).** Все места, где
 расширение обращается в сеть, перечислены и проверены: список
 доменов для блокировки (Peter Lowe's list, HTTPS,
 `AbortController` + таймаут 15 с), сервер лицензий
 (`https://belyaev.expert/bdnt-api`, таймаут 8 с, API-ключ в
 заголовке, а не в URL) - оба по HTTPS, оба с обработкой отказа сети
 без падения функциональности.
11. **Проверка гонок между `chrome.storage` (асинхронно) и
 `document_start` контент-скриптами (синхронно).** Этим способом
 найден баг с непереключаемым режимом «динамическая защита».
12. **Локализационная проверка `_locales/en` и `_locales/ru`** на
 структурное соответствие ключей (нет ли ключей, используемых в
 коде, но отсутствующих в JSON локали).
13. **Функциональная проверка через встроенную страницу самопроверки**
 (`test.html` → после фикса `test.js`) - она же является собственным
 QA-инструментом расширения: показывает расхождение между реальными
 и подменёнными `navigator`/`screen`/`canvas`/`WebGL` значениями.

## Часть 2. Рекомендуется дополнительно перед публикацией в сторах

Эти инструменты не запускались в рамках текущего (локального,
статического) аудита - окружение не имеет доступа к живому браузеру и
интернету - но являются стандартной практикой перед публикацией
браузерного расширения и рекомендуются владельцу проекта:

14. **Chrome DevTools / Yandex Browser DevTools / Opera DevTools**
 (`F12` → Console, Network, Application → Storage) - живая проверка
 в целевых браузерах: то самое место, где пользователь увидел баги
 на скриншоте (`chrome://extensions` → «Ошибки»).
15. **`chrome://extensions` → «Ошибки» / «Обзор Manifest»** - встроенный
 в сам браузер валидатор манифеста и рантайм-ошибок, идентичный для
 Chrome, Yandex Browser и Opera (все три - на Chromium).
16. **Chrome Web Store Developer Dashboard - автоматическая проверка
 при публикации** (статический анализ манифеста, permissions,
 remote code, обфускация) - обязательный шаг перед реальным релизом
 в магазин.
17. **CRXcavator / crx.dev (или аналог)** - независимый скан
 опубликованных `.crx`/`.zip` пакетов расширений на избыточные
 permissions и известные небезопасные паттерны.
18. **VirusTotal (проверка ZIP-архива пакета)** - репутационная
 проверка собранного архива перед публичным распространением ссылки
 на скачивание.
19. **ESLint** (например, с `eslint-plugin-no-unsanitized`) - линтер,
 который поймал бы класс бага «переменная не в той области
 видимости» и потенциальные DOM-XSS синки автоматически на этапе
 разработки, до ручного аудита.
20. **web-ext lint** (инструмент Mozilla, применим и к MV3-пакетам с
 оговорками) - дополнительная статическая проверка структуры
 расширения.

## Итог по этому релизу

Из перечисленного в Части 1 (13 пунктов, реально применены) в коде
найдено и исправлено 6 дефектов - подробности см. в
[CHANGELOG.md](CHANGELOG.md) и разделе «История версий» в
[DEVELOPMENT.md](DEVELOPMENT.md). Самый серьёзный - критичная поломка
всего движка подмены цифрового отпечатка на уровнях защиты 2-5,
воспроизводящая ошибку `ReferenceError: seed is not defined` из
скриншота пользователя.
